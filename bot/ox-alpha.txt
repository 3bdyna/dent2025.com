MY APPROACH IN ONE LINE:
  A UI-agnostic automation core (state -> classifier -> uploader -> harvester
  -> controller) that emits events to a fast native-window GUI as the primary
  control surface — with the console kept as a bulletproof fallback — where
  every guard is specified to the character level and every rule has a test.

CHANGELOG v3 -> FINAL (v4):
  + Adopted from Antigravity v3 (their six genuinely good UX ideas):
    (a) Document quick-preview button (open the actual file before deciding).
    (b) GAS webhook ping-test button (in Settings AND the First-Run Doctor).
    (c) Batch actions: Approve-All (AI decisions) + Ignore-All admin noise.
    (d) Re-Upload action in upload history (only when local copy still
        exists — honest scoping, see D22).
    (e) Autostart toggle via Windows registry Run key — stdlib winreg,
        zero dependencies (upgrades my documented shell:startup recipe).
    (f) System tray + toast notifications — included, but as a gracefully
        degrading optional layer with NAMED dependencies and feature flags
        (fixes their dependency hand-waving).
  + FIXED from their version: zero emojis in the UI (house AGENTS.md design
    rule) — clean inline SVG icons only; GUI phase now has a full test suite;
    single-instance mutex, rotating logs, shutdown protocol, timeout budget
    all retained (they still lack these).

PART A — ARCHITECTURE
================================================================================

A1. MODULE MAP (7 modules + GUI assets, one direction of dependency)

                      main.py (BotController — UI-agnostic)
                        |            |                |
       emits events     v            v                |
                 bb_harvester   gdrive_uploader ----> GAS webhook
                   |            ^
                   v            |
               ai_classifier ---+
                   |
                   v
              state_manager (SQLite: processed_items + pending_reviews)

       Front-ends (pick ONE at boot):
         src/gui_app.py  [default] -> pywebview window (gui/index.html)
         --cli flag                -> ConsoleSink (v2 console UX)

A2. EVENT BUS CONTRACT (plain dicts over queue.Queue)
    -> worker emits:  log{level,msg} | review_new{review} |
       review_update{id,fields} | status{auto,interval,last_scan,
       uploaded_total,pending_count,session_ok} |
       scan_started | scan_done | session_lost | session_restored
    <- GUI calls (pywebview js_api): scan_now() pause() set_interval(sec)
       approve(id) reject(id) later(id) rename(id,name)
       set_subject(id,subject_id) toggle_category(id) open_folder(id)
       preview_file(id) open_drive(url) run_login_helper() get_events()
       get_history(query) batch_approve_all() batch_ignore_noise()
       ping_webhook() save_settings(dict) set_autostart(bool)
    Polling (get_events, 300ms JS timer) chosen over evaluate_js pushes:
    no cross-thread JS injection races, survives window reload.

A3. DEPENDENCY BUDGET (fully accounted — no hand-waving)
    Required:  playwright, requests, pywebview.              (3)
    Optional:  pypdf, python-pptx, python-docx  (better AI text extraction;
               degrade to filename-only if absent)
    Optional:  pystray + Pillow (tray), winotify (toasts)    (feature-flagged,
               bot runs perfectly without them)
    Everything else: Python 3.11 stdlib (sqlite3, winreg, ctypes, winsound,
    logging, unittest, http.server for test mocks).

PART B — CORE ENGINEERING DECISIONS (unchanged armor, D1-D11)
================================================================================

D1  ITEM IDENTITY — content-derived 3-tier: xid-/pid-/dt-content-rid-/file/
    regex -> DOM id / data-content-id ("outline_f_<id>") -> djb2 base36 of
    "course_id|title|firstHref" (course_id in the seed prevents cross-course
    collisions). Positional IDs are a last resort. Seen-set merges Stream +
    Outline sources so one file found twice is processed once.

D2  DOWNLOAD PIPELINE — trust bytes, never status codes.
    1) Content-Length pre-check: skip >200MB before downloading.
    2) requests.Session fast path: cookies from storage_state.json, browser
       UA, Referer=stream URL; 2 retries with exponential backoff on
       ConnectionError/Timeout.
    3) Tag-based HTML-disguise guard: reject if first 512 bytes start with
       "<!DOCTYPE"/"<html"/"<HTML" OR final URL hits auth markers -> session
       lost banner, abort cycle. Never save HTML as a .pdf.
    4) Magic-byte sniff (first 512 bytes): %PDF -> .pdf; PK\x03\x04 ->
       ZIP namelist: ppt/ -> .pptx, word/ -> .docx, xl/ -> .xlsx, else
       genuine .zip. Extensions fixed BEFORE naming/uploading.

D3  ZIP-SLIP GUARD — exact check, every member:
        dest = os.path.realpath(os.path.join(target, member))
        if not dest.startswith(os.path.realpath(target) + os.sep): skip+log
    realpath resolves Windows junctions/symlinks; the os.sep suffix kills
    the "temp_downloads_evil" prefix trick. ".."/absolute members skipped
    AND logged. Zip contents become individual review items (parent zip
    noted in reasoning).

D4  SESSIONS — two doors, atomic swap.
    Door A: headless Chromium + storage_state -> /ultra/stream ->
    is_session_authenticated(). TOTP screen -> code requested in GUI dialog
    (or console input in --cli), screenshot opened via os.startfile.
    Door B: login_local.py visible Chrome, persistent state/chrome_profile/,
    --disable-blink-features=AutomationControlled, cookie pre-load for
    INSTANT MATCH, SSO email/pass, human types SMS 2FA, KMSI auto-click.
    Export protocol everywhere: write storage_state.json.tmp -> verify
    authenticated landing -> os.replace(). A crashed login can NEVER destroy
    the last good session.

D5  CONCURRENCY — GUI mode needs no input() at all; the v2 shared input_lock
    applies only to --cli. Worker thread pushes events to queue.Queue; GUI
    polls. Manual-scan flag prevents overlapping harvests; sleep is
    threading.Event.wait(interval) so Scan Now / Quit wake instantly.
    sys.stdout.reconfigure(encoding="utf-8") at boot for Arabic-safe console.

D6  DEDUP — three layers. (1) item_id in processed_items (uploaded|ignored
    count; no_files does not). (2) MD5 streamed in 64KB chunks vs uploaded
    history AND open pending_reviews. (3) batch filename dedup: second file
    standardizing to the same name in one cycle gets " (2)" before ext.

D7  CLASSIFIER — Arabic normalization FIRST (strip tatweel \u0640; alef
    [إأآٱ]->ا; ة->ه; ىئ->ي; diacritics \u064B-\u065F\u0670 stripped;
    lowercase), then 4-tier resolution: course-code regex (DIG311) -> full
    BB course_id substring -> exact EN/AR name -> section keywords.
    Gemini 2.5 Flash: temperature 0.1, responseMimeType application/json,
    strict JSON, ``` fence stripping, 20s timeout. ANY failure -> heuristic
    fallback (admin-noise regex -> ignore; book/manual/summary/revision ->
    material; else chapter). Empty key / dead quota never crashes the bot.

D8  MEMORY SAFETY — 45MB cap checked on disk BEFORE base64; GAS socket
    timeout 120s (large payloads on residential uplinks).

D9  TEMP HYGIENE — cycle-tracked downloads deleted in finally; only
    pending_reviews/ copies survive; 7-day orphan sweep at boot.

D10 TIMEOUT BUDGET (every wait has a number): Playwright goto 30s |
    networkidle 15s | expect_download 60s | requests 45s | Gemini 20s |
    GAS upload 120s | subtree hydration 5s. All Playwright waits wrapped
    try/except TimeoutError -> log -> continue. One bad course never
    stalls the loop.

D11 SQLITE DISCIPLINE — WAL + busy_timeout=5000; writes only on worker
    thread; GUI reads via js_api snapshot queries.

C3. CONTROL PARITY (full control — every v2 console action is a button):
    Approve -> upload by category; card flips to ✓ with Drive link.

PART D — NEW DECISIONS INTRODUCED IN v3/FINAL (D12-D24)
--------------------------------------------------------------------------------
D12 pywebview engine choice (rationale as C1; Tkinter rejected: dated look,
    painful Arabic/RTL; Electron/Flask rejected: bloat/ports/browser tab).
D13 First-Run Doctor (see C6).
D14 Single-instance guard: ctypes CreateMutexW("dent2025_bb_bot"); if
    ERROR_ALREADY_EXISTS -> focus existing window (or print in --cli), exit.
    Two instances can never race the SQLite DB or session file.
D15 Logging & alerts: RotatingFileHandler bot.log (2MB x 3) mirroring every
    event; new-file sound + taskbar flash (C5 fallback path).
D16 Autostart: stdlib winreg writes HKCU\\...\\Run "Dent2025BBot" ->
    "Start Bot (GUI).bat" path; toggle in Settings; off by default.
D17 Graceful shutdown: window X -> dialog [Minimize][Quit]; Quit sets stop
    Event, joins worker within 10s (never mid-upload/mid-write), closes DB,
    exits. Same path as --cli 'q'.
D18 CLI fallback retained verbatim from v2 (cards, listener thread,
    input_lock, --once --interval --manual --yes --no-input) — debugging
    escape hatch when the GUI misbehaves at 3 AM.
D19 Webhook ping semantics: POST {action:"ping"}; ANY HTTP 200 JSON reply
    (even success:false "unknown action") proves reachability; network error
    = red row. Honest signal, no server-side changes needed.
D20 Batch actions: Approve-All applies AI suggestions sequentially with
    per-file results; Ignore-All only touches items the classifier marked
    admin-noise; both require one confirmation click. Never batch-approve
    items with missing suggested_subject_id.
D21 Document preview: os.startfile(local_filepath) from pending_reviews/;
    button disabled (tooltip explains) after upload deletes the copy.
D22 Re-upload (history): enabled ONLY if the local copy still exists
    (pending_reviews); otherwise disabled with tooltip "re-download via a
    new scan" — no silent fake re-uploads.
D23 Settings persistence: writes config/.env atomically (tmp+replace),
    preserving unknown keys and comments where possible; secrets masked in
    UI; never echoed to logs.
D24 Optional tray/toast layer with named deps and graceful degradation (C5).

         standardized filenames incl. [Practical] prefix).

         xlsx, HTML trap, djb2 stability; Playwright in wrappers only;
         --selftest live probe).

         --cli). Tests: v2 controller suite re-run + event-order assertions
         (boot -> resume_pending -> status -> scan…) against FakeSink.
PHASE 6  gui_app.py + gui/index.html + optional tray/toast layer.
         Tests (test_gui_bridge.py): event schema validation, queue drain
         order, doctor checks on faked fs/env, webhook-ping semantics vs
         mock server, rename/subject/category mutation helpers, settings
         atomic writer. GUI itself: manual smoke checklist in README
         (launch, approve/rename/ignore fixture review with mocked
         uploader, doctor red-row flows) — no brittle UI automation.
PHASE 7  Launchers + README + smoke: Start Bot (GUI).bat [default],
         Start Bot (CLI).bat, Scan Once.bat, 1-Click Login.bat,
         Open Blackboard.bat, Run Tests.bat (all chcp 65001, cd /d "%~dp0").
         README: install (pip install playwright requests pywebview
         [pypdf python-pptx python-docx pystray Pillow winotify] +
         playwright install chromium), GUI tour, Doctor troubleshooting,
         autostart, session recovery, first-run smoke: Doctor green ->
         Scan Once --no-input -> inspect queue -> approve a few cards ->
         only then trust 24/7 / --yes.

PART F — TESTING & RISK REGISTER
--------------------------------------------------------------------------------
~55 offline deterministic tests (unittest, zero new test deps). Every
Hard-Won Rule maps to a named decision AND at least one test.

R1  Session loss mid-cycle ... HTML guard + banner + atomic export ... D2/D4
R2  Duplicate uploads ........ item_id + MD5 + batch-name dedup ...... D6
R3  Reordered stream ......... content-derived IDs only .............. D1
R4  Fake HTML download ....... tag-based byte guard .................. D2
R5  Wrong extensions ......... ZIP-namelist sniff (incl xlsx) ........ D2
R6  Zip-Slip ................. realpath + os.sep containment .......... D3
R7  Hung waits ............... timeout budget + try/continue ......... D10
R8  Arabic mismatch .......... normalization first ..................... D7
R9  Console deadlock (--cli) . single shared input_lock ............... D5/D18
R10 Temp litter .............. finally cleanup + orphan sweep ......... D9
R11 Big-file bandwidth ....... Content-Length pre-check .............. D2
R12 Transient net blips ...... 2 retries, exponential backoff ........ D2
R13 DB lock contention ....... WAL + busy_timeout + single writer .... D11
R14 GUI thread races ......... queue.Queue + polling, no shared UI
                             state, js_api marshaling ................ A2/D5
R15 Two instances ............ named mutex ........................... D14
R16 WebView2 missing ......... runtime detect + --cli suggestion ..... C1
R17 GUI bug blocks bot ....... controller fully usable via --cli ..... D18
R18 Silent GUI failures ...... bot.log mirrors everything ............ D15
R19 Batch-action mistakes .... confirmation + noise-only scoping ..... D20
R20 Fake re-uploads .......... local-copy existence check ............ D22
R21 Secret leakage ........... masked fields + atomic .env writer +

PART G — WHY THIS FINAL PLAN WINS
--------------------------------------------------------------------------------
1. User's brief — fast, full control, easy and clear: native-speed WebView2
   window, every action one button, Doctor prevents first-run confusion,
   house dark aesthetic, zero emojis, RTL-safe. Console fallback guarantees
   the bot is NEVER unusable.
2. Best-of-both: absorbed the competitor's six best UX ideas (preview,
   ping test, batch actions, re-upload, registry autostart, tray/toasts)
   while fixing their flaws — emoji violations, unnamed dependencies,
   untested GUI phase, missing instance/log/shutdown hardening.
3. Safety core untouched and character-precise: Zip-Slip realpath guard,
   atomic session swap, 3-layer dedup, timeout budget, retries — every rule
   traceable to a decision and a test (~55 suites-green tests).
4. Honest engineering: dependency budget fully accounted (3 required,
   optional extras feature-flagged), Re-Upload scoped to reality, ping
   semantics defined, secrets handling specified. No marketing numbers —
   just what ships.
